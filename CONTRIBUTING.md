# Contribution guide

- Start only after the organiser announces kick-off.
- Reproduce a reported issue before changing code.
- Use a focused branch per issue: `fix/issue-<number>-<summary>`.
- Use `feature/<short-name>` for features.
- Commit with `fix(scope): explain change` or `feat(scope): explain change`.
- Run `python -m pytest -q`; never remove or weaken tests.
- Open pull requests containing root cause, changes, tests run and known limitations.
- Be ready to explain and modify your code during the viva.
